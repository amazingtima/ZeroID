# Zero ID

Веб-приложение, которое скрывает персональные и конфиденциальные данные в тексте и в документах Word. Каждый найденный символ заменяется на `*`.

Вся обработка идёт локально в браузере. Данные не отправляются на сервер, не сохраняются в `localStorage` и исчезают при закрытии страницы, поэтому приложение можно разместить на статическом хостинге вроде GitHub Pages.

## Возможности

- Маскирование текста, вставленного в поле, и файлов `.docx` до 10 МБ
- Поддержка русского, казахского и английского языков в интерфейсе и в детекторах
- Скачивание обработанного документа с сохранением исходного форматирования
- Переключатель языка, копирование выделенного фрагмента, очистка поля

## Что распознаётся

Детекторы разделены по надёжности.

По контрольной сумме: ИИН и БИН (модуль 11), IBAN (модуль 97), номера банковских карт (алгоритм Луна). Ложные срабатывания практически исключены, поэтому длинные номера договоров и артикулы остаются нетронутыми.

По формату: телефоны Казахстана с префиксом `+7` и `8`, email, IP-адреса, MAC-адреса, JWT и ключи вида `sk-...`, автомобильные номера, VIN, координаты, ники через `@`, даты в любом написании.

По ключевому слову рядом: номер удостоверения личности и паспорта, CVV.

По метке поля: строки вида `метка: значение` — адреса, суммы, названия банков, пароли, номера полисов, медицинские сведения и прочее, что невозможно описать шаблоном. Метки заданы для трёх языков; в казахском сопоставление идёт по основе слова, поэтому притяжательные окончания вроде «мекенжайы» или «нөмірі» подхватываются автоматически.

ФИО определяются по цепочке слов с заглавной буквы и опорным окончаниям. Отчества и казахские `-ұлы`, `-қызы` считаются надёжными сами по себе, фамильные `-ов`, `-ев`, `-баев`, `-sky` работают только внутри цепочки, иначе обычные слова вроде «Пунктов» попадали бы под маску.

## Ограничения

Чисто английские фамилии без узнаваемых окончаний (`John Smith`) в свободном тексте не распознаются — без словаря имён их не отличить от названий компаний. В полях с меткой такие имена скрываются.

Текст внутри картинок и сканов, вложенных в документ, не маскируется: для этого нужен OCR.

Если рядом с фамилией стоит другое слово с заглавной буквы, оно тоже попадёт под маску. Это осознанный выбор в пользу безопасности.

## Как работает обработка docx

Файл `.docx` — это ZIP-архив с XML внутри, поэтому он распаковывается через `fflate`, изменяется и собирается обратно. Разметка не пересобирается парсером: подменяются только символы внутри текстовых узлов по их смещениям, за счёт чего шрифты, стили, таблицы и картинки остаются без изменений.

Word разбивает фразы на несколько текстовых узлов, поэтому текст склеивается на уровне абзаца, маскируется целиком и раскладывается обратно по узлам. Для анкет в виде таблицы первая ячейка строки считается меткой, а остальные — значением.

Кроме тела документа обрабатываются колонтитулы, сноски, комментарии и свойства файла `docProps`, где Word хранит автора и последнего редактора.

## Разработка

```bash
npm install
npm run dev
```

Сборка и проверка типов:

```bash
npm run build
npm run typecheck
```

## Стек

React 19, TypeScript, Vite, fflate. Фон рисуется на canvas без сторонних библиотек.

## Структура

```
src/
  App.tsx                    корневой компонент и состояние языка
  i18n.ts                    словари для ru, kk, en
  index.css                  все стили приложения
  components/
    PromptComposer.tsx       поле ввода, кнопки, загрузка и скачивание файла
    LangSwitch.tsx           переключатель языка
    Aurora.tsx, DotField.tsx фоновая графика на canvas
  lib/
    redact.ts                детекторы данных и маскирование текста
    docx.ts                  разбор и сборка docx
```
